# Module split map

Where every declaration lives, and the seams that keep the split safe. The line
ranges below describe the tree that adds `src/delivery.ts`: `src/index.ts` is
7,007 lines and `src/delivery.ts` is 372. They are a reading aid, not an API —
re-scan after a commit instead of trusting an offset.

## Artifact and build

- The loadable mod is the repo-root `better-sub-agents.ts`, generated by
  `scripts/build.mjs` (esbuild, ESM, `platform: node`, `minify: false`,
  `keepNames: true`) from `src/index.ts`.
- `src/` is the only place to edit. `npm run build` regenerates the root file;
  `npm run gate` fails if the committed root file is stale.
- `src/index.ts` is the entry (`export default function (cmd, overrides)`); it
  re-exports the public surface the host, `test/e2e.mjs`, and `test/harness.mjs`
  import.
- `scripts/check-imports.mjs` enforces the module rules: only the entry may
  name `./index.ts`, runtime imports may not cycle, and `./types.ts` is
  type-only.

## Seam rules

1. **`MOD_PATH` and `WORKER_SOURCE` stay in the entry.** They are the two
   bundle-literal symbols: `MOD_PATH` reads `import.meta.url` (with the
   `.load-N` strip for jiti's virtual filename) and `WORKER_SOURCE` is one
   template string through :1326. Neither may be imported by a leaf: the entry
   is their only consumer, so the bundler emits both in the root file and a
   leaf that needs the mod path takes it as a `modPath` parameter instead
   (`buildSpec(input, modPath)`). `MOD_PATH` is defined in
   `src/constants.ts:94` today and is treated as entry-owned.
2. **No module imports `./index.ts`.** The entry depends on leaves, never the
   reverse. `scripts/check-imports.mjs` fails the gate if this is violated.
3. **Imports point downward only, without runtime cycles.** The graph is a DAG:
   `index → every leaf`, `delivery → {constants, jobs, ledger, signals, state, types}`,
   `signals → state`, `signals → types`, `jobs → types`, `ledger → types`,
   `append → types`, `tool-filter → constants`, `worktree → types`.
   `types.ts` is a type-only leaf: import it with `import type`. A new shared
   symbol goes in the lowest module that needs it, not in the entry.
4. **Embedded source stays self-contained.** `WORKER_SOURCE` calls
   `.toString()` on `signalEnvelope` and `scanOutput` at module load, so both
   bodies must stay plain, reference-free JavaScript. Do not "clean up"
   `import.meta.url`, the template literal, the `require(...)` calls inside it,
   `process.pid`, or `node -e`.
5. **Side effects arrive as arguments.** A leaf takes `fs`/`run`/`now`/`env`
   or a deps object. Only the entry (via the runtime adapter) touches the real
   OS.
